## Implementation and decisions

- **CTX-01:** Extend existing conversation and presentation models with
  `target_slide_count`, `special_instructions`, `professional_scope` and
  `is_multidisciplinary`. Retain `objective` for learning objectives and all
  existing topic/audience/duration/language/type/title metadata.
- **CTX-02:** Require explicit nonblank instructions; users can enter “None” /
  “Aucune”. Do not infer missing instructions. The target count is a strict
  integer from 1 to 200, an operational input bound rather than a PRD-defined
  limit or a guarantee about generated/exported slide count. Retain the existing
  1–480 minute API range and reject Boolean/coerced duration input.
- **CTX-03:** The professor explicitly chooses whether the topic is
  multidisciplinary and confirms professional scope. A multidisciplinary topic
  additionally requires a competence confirmation. Checkboxes start unchecked.
  This is a human declaration, not automatic subject classification or proof of
  competence. Existing profile/resource mismatch checks remain in place.
- **CTX-04:** Bind confirmation to the authenticated actor, server UTC timestamp
  and a SHA-256 digest of topic, audience, type, language, duration, objectives,
  target count, instructions, scope and multidisciplinary choice. Persist state
  and an approval event in the existing SQLite transaction. The audit stores
  the digest and confirmation metadata without duplicating raw scope text.
  Subsequent existing scope clarification preserves this context binding.
- **CTX-05:** New fields default to `None` in stored models so old Projects can
  load without fabricated answers. The setup endpoint also completes missing
  legacy context. Existing non-null fields are preserved; replacement attempts
  fail. It synchronises all three context representations and preserves the
  presentation ID, resources, slides and workflow progress. General context
  editing and its output invalidation are not added in this slice.
- **CTX-06:** A shared deterministic policy blocks dependent API actions,
  queued/reloaded generation and generation-chain calls when context or its
  attestation is missing/stale. The workflow view exposes the context form for
  incomplete legacy Projects. Project/audit reads, resource removal/detachment
  and independent source analysis remain available under existing protections.
  A different context digest invalidates the attestation even if legacy free-text
  scope exists. Chat tools cannot manufacture an authenticated attestation.
- **CTX-07:** Extend the existing `/app` FR/EN setup form and lock already saved
  fields during legacy completion. Pass the count/instructions into the existing
  Blueprint prompt as user guidance, subject to existing safety/evidence rules.
  No planning algorithm, dashboard expansion or autosave redesign was added.

Architecture, owner isolation, prototype policy, source controls, atomic saves,
revision checks and job locks are retained. Streamlit has no new interface work.
All new test data is synthetic; no external model provider was used.

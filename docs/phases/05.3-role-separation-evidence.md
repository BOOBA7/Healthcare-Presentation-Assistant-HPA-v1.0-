# 05.3 — Evidence import, explicit graphic reuse and old-deck warnings

Status: implemented; product-owner acceptance of 05.3 and the phase 05 gate
remain pending. Starting HEAD: `0a31246`, with a clean working tree. The owner
subsequently authorised committing and pushing this implementation; this is
not product acceptance of 05.3 or the phase 05 gate. Only public/synthetic fixtures
were used; no provider call, dependency installation or Streamlit change.

## Decisions and observable behaviour

### Separate roles (FR-04, FR-05, FR-13)

Evidence import retains the original, slide locations and derived assets. It
never selects a template or changes the theme. The existing template gallery
now also offers the Project's PPTX originals through an explicit **Use template**
action, enabled after Blueprint approval. The authenticated owner selects the
source identifier and submits the Project revision. The original is screened
again; this action neither selects scientific evidence nor confirms OCR/assets,
changes provenance or approves scientific content.

The existing dedicated template-upload route now uses the same bounded
`SourceDocument`/PPTX reader as evidence import, including scientific dates,
privacy, notes, metadata, relationship and opaque-content checks. Direct
repository calls cannot bypass that reader. Template registration and its
owner audit event commit together. Originals and retained derivatives use the
existing private owner-source SQLite records; template registrations contain
only a source identifier. No new independent template file or cache is created.
An original imported solely for graphics stays outside the Project's evidence
library and model context. Adding it as evidence remains a separate action.

This intentionally narrows the previously permissive template route. Old
unchecked on-disk templates are not automatically grandfathered in or cleaned
up into accepted packages. They must be reimported through the common reader.
Undated, opaque, malformed, disguised and unsupported packages remain refused.
Pending extraction review does not grant scientific eligibility merely because
the original can be used graphically after privacy screening.

Reuse uses the existing export mechanism: retain the supplied masters/layouts,
remove sample slides and apply existing HPA rendering. It does not implement
phase 09's style engine or promise reproduction of the source deck's appearance.
Exports accept a verified original Resource, not an arbitrary template path.

### Conservative warnings (FR-18)

Every PPTX evidence citation keeps the exact warning:

> Source: user-supplied presentation — primary reference unavailable.

There is no claim-to-primary-source verification workflow in the current
application. A bibliographic mention, DOI-like string, reference list, another
uploaded document, asset attribution or caller/model flag cannot establish
that relationship. Consequently the warning is retained for all PPTX evidence,
including when a candidate primary reference is present but unverified,
ambiguous or not attributable. No external source is fetched. No author, DOI,
rights or date is invented. Introducing a qualified attribution workflow is
outside 05.3; this conservative fallback does not claim that every supplied
deck literally lacks bibliographic text.

Warnings are derived from the canonical resource type, not a mutable approval
flag. They accompany retrieved excerpts (including persisted-chunk retrieval),
Python/web citation labels, source cards, slide review and preview, and the
existing PowerPoint claim/reference slides. API display projections regenerate
the labels after restart or deserialization. Export regenerates warnings rather
than trusting caller-supplied reference flags. For PPTX references, the
provenance validator replaces model-supplied bibliography fields with original
source descriptors, retaining the resource ID, source slide and exact passage;
passage matching is not verification of a primary publication. The underlying
source text and scientific-date evidence are unchanged.

This uses existing citation/slide boundaries. It is not the complete claim
coverage, human-authored claim validation or final citation-layout work of
phases 06/08/10. Human-authored or edited slides retaining a PPTX reference also
retain the warning. A claim with no source locator cannot acquire a source
attribution from this feature.

### Persistence, concurrency and deletion (FR-22, NFR-02, PRD §11)

Style changes go through one repository operation. Direct state saves and
serialized objects cannot install or replace a template/theme. Optimistic
Project revisions, active-job exclusion, source ownership and deletion markers
protect the transaction. Style, invalidation and descriptor-only owner audit
are atomic; audit failure rolls back the entire operation. Imports are also
atomic with their library audit event. Audit descriptors include identifiers,
workflow stage/status and hashes, not extracted text or image bytes.

A style change invalidates slide/final approval and internal exports, while
retaining evidence, extraction reviews and Blueprint approval. Since the
existing application combines scientific and visual slide approval, its slide
approval flag is conservatively reopened. A removed evidence original clears
its graphic link as well. Permanent deletion includes graphics-only links and
template registrations, and uses existing secure SQLite/export cleanup.
Deleting a graphics-only original reopens visual approval without discarding
unrelated scientific evidence or Blueprint approval. Removing an evidence
source retains the previous conservative source-invalidation policy.

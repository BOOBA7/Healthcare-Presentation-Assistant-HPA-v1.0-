## Delivered behaviour and decisions

1. `PrototypePolicy` is the shared deterministic policy. Only explicit `public`
   or `synthetic` declarations allow processing. Patient flags are refused even
   with acknowledgement; `EXECUTION_MODE` defaults to `public_prototype`, and
   any other execution mode is unavailable. Explicit patient-case/confidential
   markers in supported text are rejected with safe errors that omit matched text.
2. `/projects` records the owner's whole-Project assertion and external-processing
   acknowledgement using the existing atomic state/event write. Events include
   authenticated identity, timestamp, policy version and disclosure. New and old
   snapshots default to **undeclared**, never silently accepted. The declaration
   is copied to the presentation when created/redeclared.
3. `/app` displays an always-visible FR/EN disclosure in the Project sidebar,
   a public/synthetic choice and an initially unchecked acknowledgement. Existing
   provider adapters are retained; the disclosure names OpenAI/Gemini and explains
   what is sent externally. Patient-mode controls are removed. Retrieval selection
   remains unchanged for 01.3. Browser rendering is not yet verified.
4. API JSON input and synchronous handlers screen content before durable content
   writes. PDF extraction requires a declaration and screens extracted text and
   metadata before library insertion. No implicit Project creation through chat.
   Shared resource/overview/discussion/agent/generation paths enforce the policy.
5. Jobs validate before enqueueing and reload authoritative Project state inside
   workers. A queued task cannot continue after the stored state becomes a patient
   Project. Existing durable failure handling records the refusal as a failed job.
6. `get_llm` checks mode before returning even a cached adapter. Both adapters
   receive a fail-fast model callback that rechecks mode and non-system prompt
   content before invocation, including on a cached model. Shared entry points
   separately screen state/resources/chunks; trusted system safety instructions
   are excluded from the callback's text-marker check.
7. Existing PPTX **template** ingestion also requires an explicit declaration and
   acknowledgement, screens XML text including notes, and persists the declaration
   with the existing owner/timestamp metadata. An additive nullable SQLite column
   preserves old rows; undeclared old templates are unavailable until reuploaded.
   This does not implement PPTX evidence ingestion or phase 05.
8. Reading/deleting legacy Projects remains possible. Legacy patient flags cannot
   be cleared by redeclaration or evidence-settings updates. Shared restrictions
   also block legacy Streamlit processing without adding a declaration UI there.

## Remaining limits and next action

The boundary enforces declarations and explicit forbidden settings/markers, not
semantic document classification. A false declaration with unrecognised restricted
content can evade text screening; automated detection cannot prove anonymisation.
Images, faces, OCR, embedded binaries and comprehensive identifier/re-identification
analysis are not verified here. Public scientific dates remain allowed; this is
not the later scientific-date gate. Template text screening does not certify its
images or embedded assets. Professional mode remains unavailable; this implementation
must not be interpreted as clearance for professional data.

No change to claim-level evidence/export gates, roles/languages, unauthenticated
recovery, or comprehensive owner-isolation verification. These remain assigned to
their phases/slices. Phase 01 owner approval, pilot observations, competent external
reviews and scientific validation remain pending. **Stop after 01.1.** Next exact
slice is **01.2**, requiring separate authorisation. Node/browser gaps remain open.

Engineering note: fail-closed defaults require a positive declaration before
processing. Rechecking inside a worker prevents the queue's earlier decision from
being reused after the saved Project state changes.

# 05.1 — Restricted PowerPoint evidence import

Status: implemented and explicitly approved by the product owner on 2026-09-17
for the restricted subset documented below. Implementation commit: `f699481`;
the subsequent handoff/approval documentation is recorded by `5fbf98b` and
`cfc7dde`. This is a historical evidence summary reconstructed from the
contemporaneous phase-05 handoff; no check has been rerun for this document.

## Implemented boundary

- Screened in-memory PPTX import accepts native slide text and simple tables,
  preserves one-based source-slide locations, and retains the exact original,
  hash and minimal descriptors across restart.
- Evidence import does not select or alter the presentation theme or template.
- The bounded OOXML package is screened before acceptance, including notes,
  core/extended/custom properties, shape names, alternate text, filenames,
  relationships and reachable XML parts.
- External, dangling or unknown relationships; opaque/orphaned parts;
  encrypted, malformed or ambiguous ZIP/XML; unsupported drawings/objects;
  unsafe metadata; conflicting/missing scientific dates; limit violations and
  disguised formats fail closed before a durable raw write.
- Source verification covers service, presentation, repository, API, restart,
  owner isolation, model-context and permanent-deletion boundaries. DOCX,
  spreadsheets and DICOM remain rejected.
- Audit payloads retain descriptors without copying notes or extracted medical
  text. Existing privacy, date, OCR and pre-model gates remain authoritative.

## Limits and decision

The two browser scenarios were skipped on unsupported macOS 10.15. No real
browser inspection, visual-rendering validation, external provider call,
professional document, patient data or scientific assessment was performed.
The synthetic native probes do not establish anonymisation, detector accuracy
or visual fidelity.

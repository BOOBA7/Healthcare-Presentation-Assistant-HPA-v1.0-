## Decisions and implementation

- **SRC-032-01 — Atomic originals:** Add nullable `original_pdf BLOB` to the
  existing `project_resources` table through an additive migration. Store accepted
  PDF bytes in the same transaction as metadata, exact extracted pages, chunks,
  Project revision and upload audit. This avoids a second filesystem transaction
  and orphan original files. Existing `content_hash` remains the normalized
  record hash; `metadata.original_sha256` is distinctly the hash of original bytes.
- **SRC-032-02 — Memory and integrity:** Keep the original on a Pydantic private
  attribute while in memory, excluded from JSON/model prompts. Re-extract and
  screen the actual original before acceptance, repository writes, scientific
  use and download; compare text, pages, title/source, metadata, date evidence,
  locations, byte count and SHA-256 against that original. Supplied flags and
  hashes are not proof. The whole repository batch is checked before any write
  or deletion. An existing original cannot be replaced under the same resource
  ID; import a new resource instead, preserving existing approval boundaries.
- **SRC-032-03 — Metadata:** Retain standard PDF and XML metadata, title and
  author, and available Dublin Core creator/publisher/rights/source values.
  Missing organisation, rights or bibliography remain unknown; no external
  lookup or inferred licence is performed. Import timestamps use server UTC.
  Raw PDF/XML metadata remain in the library and are omitted from lightweight
  presentation selections; original bytes are never part of Project JSON.
- **SRC-032-04 — Explicit dates:** Accept standalone English/French publication
  or update labels in the first 40 extracted lines of page 1, before a recognized
  References/Bibliography heading. Supported values are `YYYY`, `YYYY-MM` and
  `YYYY-MM-DD`; precision is preserved without inventing missing components.
  Examples: `Publication date: 2024`, `Published online: 2024-02`,
  `Date de publication: 2024-02-29`, `Mis à jour le 2024-03-01`.
  Also accept the namespaced PRISM 2.0/3.0 `publicationDate` element or attribute
  from the original's XMP. Preserve the exact label/page or metadata key/value.
- **SRC-032-05 — Refusals:** Filesystem/import dates, PDF CreationDate/ModDate,
  XMP CreateDate, filenames, copyright years, reference-list years and unsupported
  declarations do not satisfy the gate. Invalid calendar dates, future dates,
  conflicting dates of the same kind and updates preceding publication are
  rejected. A consistent update is preferred over publication. This bounded
  parser rejects unsupported/ambiguous date representations rather than guessing.
- **SRC-032-06 — Legacy recovery:** Historical records remain readable and can
  be saved unchanged, detached or removed through existing operations. They do
  not acquire an invented original, hash or approval. Undated sources are blocked;
  even a dated legacy record must be reimported when its original is unavailable
  to substantiate the evidence. The historical page-1 indexing fallback cannot
  substitute for a missing original. Claiming legacy origin cannot introduce a
  new source without its original through the repository.
- **SRC-032-07 — Shared gates:** Check source eligibility before attachment,
  human resource approval, retrieval/model context, generation/regeneration,
  queued job creation and worker reload, and export. Existing human approval
  flags cannot override these checks. Refuse resource discussion before writing
  its question when sources are ineligible; preserve existing durable question
  handling for eligible-source provider failures.
- **SRC-032-08 — API/UI/audit:** `/app` displays FR/EN date evidence and source
  blockers, including missing originals, with escaped values. The Project API
  exposes bounded date evidence, hash and available bibliographic fields, not
  full pages, XML or bytes. Owner-authenticated original download returns the
  exact verified PDF as an attachment with `no-store` and `nosniff`. Upload audit
  adds original hash, date value/origin and policy version without raw PDF text.
  Workflow next actions block dependent work and request source replacement.

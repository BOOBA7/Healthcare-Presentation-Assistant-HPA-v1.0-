# Slice 02.3 — Durable actions and recovery evidence

Date: 2026-09-15. Scope: FR-02, FR-03 and NFR-02 recovery behaviour only.

## Implementation

- Material Project operations already use `save_with_event`: state, revision,
  `updated_at`, resource synchronization and audit event commit in one SQLite
  transaction. A rejected or failed transaction cannot be shown as a successful
  save.
- The existing revision comparison rejects a stale browser or job write before
  it can replace newer human work.
- Generation-job failures retain the current Project state, record a durable
  `WORKFLOW_GENERATION_FAILED` event and expose a recoverable workflow blocker.
- `WorkflowViewBuilder` now returns a deterministic `next_action`, selected
  from the active job, first blocker or allowed action. `/app` displays it with
  all server-returned blockers in English and French. The browser does not
  infer workflow order.

## Limits

This slice does not create a provider call, automatic retry, scientific
validation, human pilot, or professional-data capability. It reports durable
workflow state only; it cannot prove the correctness of a user's professional
scope declaration.

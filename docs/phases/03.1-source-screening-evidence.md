## Decisions and implementation

- **SRC-031-01 — Additive descriptors (FR-05):** `Resource.metadata` holds a
  versioned `SourceMetadata`, with media type, author, organisation, publisher,
  rights, provenance, locations, asset descriptors and string extensions.
  Location kinds accommodate pages, slides and regions; asset kinds accommodate
  images and tables. Existing title, filename, source, import timestamp and
  extracted content remain authoritative existing fields. Descriptors do not
  contain original bytes or implement asset extraction/storage.
- **SRC-031-02 — Lazy migration:** Old embedded Project JSON and normalized
  SQLite metadata are upgraded on read in memory, then persisted on the next
  successful ordinary transaction. No bulk rewrite or schema replacement is
  needed for the existing JSON column. Unknown bibliography/rights remain null;
  origin defaults to `legacy`. Only explicitly recorded page numbers populate
  locations. Old text-only resources have no newly asserted exact location.
  The existing legacy indexing fallback to page 1 remains unchanged and is
  not new evidence of an exact location. No approval or date is fabricated.
- **SRC-031-03 — Memory boundary:** The PDF endpoint uses a bounded multipart
  reader without Starlette's disk-spooled `UploadFile`. Authentication, ownership
  and Project declaration precede parsing. The existing 20 MiB file limit is
  retained, with 64 KiB multipart overhead and an operational 1,000-page limit.
  Existing PDF extraction runs in memory and closes the document on failure.
- **SRC-031-04 — Deterministic refusal:** Screen extracted page text, standard
  PDF metadata and XML metadata with the existing prototype marker policy.
  Reject encrypted/inaccessible, empty or partly unreadable documents and
  unsupported images, vector drawings, annotations, widgets, links or embedded
  attachments. Exceptions become a content-free `SOURCE_SCREENING_INCOMPLETE`
  refusal. Supporting those surfaces belongs to subsequent authorised work.
- **SRC-031-05 — Repository bypass protection:** Revalidate actual resource
  content and metadata before persistence, regardless of `is_validated` or
  claimed origin. Check library and presentation copies before normalization
  can discard a conflicting copy. Also guard direct `_sync_resources` calls
  before the first DELETE/INSERT. Missing library text, malformed pages,
  unsupported formats/assets and uninspected file paths are refused. Existing
  transactions, revision checks, owner scoping and audit remain in place.
- **SRC-031-06 — Audit:** Successful upload events retain their existing
  actor/resource metadata and add the deterministic screening-policy version.
  Refused imports produce no durable content or event writes. Existing atomic
  event persistence rolls back all source/page/chunk/Project writes if it fails.

## Limits and next slice

Screening is conservative explicit-marker detection for the public/synthetic
prototype, not comprehensive identifier recognition, anonymisation, malware
analysis or scientific validation. Unsupported PDF surfaces currently reduce
the range of accepted PDFs intentionally. Repository guards cover application
write paths; they cannot prevent a person with filesystem access from editing
SQLite through unrelated software. Original-byte inspection cannot be repeated
for historical resources because originals were never stored. Such resources
remain identified as legacy; their available persisted content is rechecked.

No original bytes/hash retention, scientific-date implementation, permanent
deletion, new format support, professional-data capability or full phase 03
acceptance is claimed. Next exact slice: **03.2**, accepted original PDF bytes,
hash, retained metadata/bibliography/rights and reliable document/scientific-date
evidence without automatic external research. Requires separate authorisation.
Stop after 03.1; do not start 03.2 or 03.3.

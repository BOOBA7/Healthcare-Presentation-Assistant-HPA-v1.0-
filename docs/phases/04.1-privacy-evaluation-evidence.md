## Decision and executable evidence

Run `venv/bin/python -m app.application.services.privacy_evaluation` from the
repository root. It probes executable/package availability, evaluates fourteen
labelled synthetic text fixtures and creates six in-memory PNG/JPEG fixtures
(blank, text, schematic face) embedded in PDFs. It emits only fixture IDs,
categories and counts. It never downloads models or writes image files.

**No production OCR configuration is qualified.** Tesseract is absent from PATH;
pytesseract, tesserocr, EasyOCR and cv2 are absent from the active venv. Pillow
and PyMuPDF are available. Real OCR trials: **0**; real face-detector trials:
**0**. No simulated OCR output is counted as a real recognition result. Failure
injection tests exercise the text gate only. Installing an engine would not by
itself establish memory-only processing, face screening or acceptable accuracy.

Shortlist, checked against primary sources on 2026-09-16:

| Candidate | Local execution / licence | Decision for this environment |
|---|---|---|
| Tesseract with tesserocr | Tesseract Apache-2.0; wrapper MIT; Pillow/in-memory API | Best candidate for a future isolated memory-only qualification, but unavailable; no accuracy, language-pack, disk-write or timeout behaviour verified |
| Tesseract with pytesseract | Local wrapper around executable; Apache-2.0 project | Reject standard image-object configuration: wrapper saves temporary input/output files before screening completes |
| EasyOCR | Local inference; Apache-2.0 project; model weights and runtime required | Unavailable; model acquisition/cache and offline execution must be explicitly controlled and verified before any use |

Sources: [Tesseract](https://tesseract-ocr.github.io/tessdoc/),
[tesserocr API](https://github.com/sirfz/tesserocr),
[tesserocr licence](https://github.com/sirfz/tesserocr/blob/master/LICENSE),
[pytesseract file handling](https://github.com/madmaze/pytesseract/blob/master/pytesseract/pytesseract.py),
[EasyOCR](https://github.com/JaidedAI/EasyOCR).
The candidate preference is an engineering inference from those APIs, not a
benchmark winner or a committed architecture/dependency change. There is no
fallback to a file-writing wrapper or external provider.

## Implemented changes and inspected surfaces

- `app/application/services/identifier_screening.py`: bounded EN/FR heuristics
  for labelled names, email/labelled or international telephone details,
  selected record/administrative identifiers, birth/admission/discharge date
  labels, addresses and age/location/occupation combinations; NFKC normalization.
  Findings expose categories only. Error messages never include source content.
- `app/application/services/prototype_policy.py`: apply the same detector to
  string values in the existing recursive gate. Existing prototype declarations,
  forbidden-content checks and disabled patient-case mode remain in force.
- `app/application/services/source_screening.py`: audit version becomes
  `source-text-metadata-v2`; retained PDF/resource checks inherit the shared gate.
- `app/ai/llm/llm.py`: direct provider callback rejects non-text/multimodal blocks;
  explicit text blocks and interpolated system text pass identifier screening.
  System instructions retain their exemption from the prohibited-topic regex,
  because they describe the prohibition itself.
- `app/application/services/privacy_evaluation.py` and
  `app/tests/test_privacy_evaluation.py`: executable evaluation and 24 new tests.

| Surface | Behaviour and limits |
|---|---|
| Text PDF pages, filename, title, bibliography, PDF Info, XMP, resource extension values | Shared heuristics before acceptance; source verification and repository rechecks preserved. No semantic name recognition or comprehensive language coverage |
| PDF images, vector drawings, attachments, annotations, widgets, links, blank/unreadable pages | Existing incomplete-screening refusal preserved. No claim to inspect pixels, EXIF/GPS, hidden embedded payloads or detect faces |
| PNG/JPEG, scanned PDFs and schematic faces | Evaluation proves refusal, not successful OCR/face detection. No new import support |
| State, retrieved context and direct configured-provider callback | Existing entry points inherit text screening; opaque model content blocks fail closed. Arbitrary independently constructed providers/SQL are outside application controls |
| Publication dates | An ordinary publication date remains allowed; identifying labels block. Existing scientific-date/original gate remains required |

Text limit: 2,000,000 characters per string, in addition to existing 20 MiB
source/payload and 1,000-page limits. Runtime errors, timeout exceptions and
interruption exceptions in the detector become a generic incomplete refusal.
There is no new hard wall-clock watchdog for native PDF parsing. Process death
cannot commit an input that has not passed the existing transactional gate.
No OCR process exists to cancel or clean up in this slice.

The detector is deliberately bounded, not an FR-08 completion claim. It can
miss unlabelled names, obfuscated contact details, unsupported languages,
identifying dates without recognized labels and combinations split across
fields. PDF extraction is not a forensic inventory of every unused object.
The source gate does not promise universal privacy or anonymisation. Real
professional and patient-case content remains prohibited.

## Observed errors

Fourteen hand-labelled text fixtures: **7 true positives, 3 true negatives,
1 false positive, 3 false negatives**. On this tiny constructed set only:
false-negative rate 3/10 = 30%; false-positive rate 1/4 = 25%.

- Missed: unlabelled synthetic full name, obfuscated email, narrative rare
  age/occupation/location combination.
- Overblocked: deliberately public editorial contact email. It is not exempted
  because an email's public/private status cannot be inferred safely here.
- Six image fixtures all return `SOURCE_SCREENING_INCOMPLETE`. This includes
  harmless blank images; these are availability refusals, excluded from detector
  confusion counts. No image/OCR/face sensitivity or specificity is measurable.

These measurements expose limitations; they do not estimate clinical or
real-world privacy performance. Improving known blind spots and qualifying
image screening remain necessary before broader format acceptance.

## Outcome and decisive limitation

The bounded pipeline can decode PNG/JPEG and simple full-page image-only PDFs
in memory, retain original bytes and normalized original-region coordinates,
derive dated provenance, persist/reload/delete those descriptors through the
existing source lifecycle, and prevent unconfirmed OCR from scientific/model
use. Automated positive-path tests use an explicit engine double.

An additional local capability was discovered beyond the 04.1 Python shortlist:
Apple Vision, with macOS 10.15 SDK and an installed native compiler. Real OCR
and face requests were executed through an Objective-C adapter compiled locally.
The engine was confined with macOS `sandbox-exec`, denying file writes and
network access; no image input/output temporary files were used. A containing
Codex sandbox initially prevented `sandbox_apply`; the same experiment was run
outside that containing sandbox with user-approved escalation, keeping the
engine's own restrictions. There is no fallback to unconfined execution.

**Real results do not qualify the engine for acceptance.** A labelled name and
email were blocked; an unlabelled name and schematic face were missed. The
production `LocalImageScreening.inspect` therefore always refuses. Only the
explicit evaluation method can invoke the native experiment. There is no
configuration flag, environment variable, client field or UI switch that enables
it for ingestion. Building the binary does not unlock formats. The web picker
continues to offer PDF only; scans and direct PNG/JPEG API attempts fail closed.
Do not interpret passing doubled integration tests as delivered production
format support or FR-08 compliance.

## Native experiment and reproducibility

```sh
venv/bin/python -m app.interfaces.ocr.build_vision
venv/bin/python -m app.application.services.raster_evaluation
```

The optional compiler output is ignored in `app/interfaces/ocr/.build/`.
Compilation occurs before input processing and consumes only source code.
Apple's system frameworks are linked, not copied or redistributed; this is an
OS-specific experimental capability, not an open-source OCR dependency choice.
Tesseract/tesserocr/EasyOCR remain unavailable. No package was downloaded.
Pillow 12.3.0, already installed, is now an explicit pinned direct requirement.

The installed SDK exposes revision 1 text recognition and face rectangles;
`VNRecognizeTextRequest.supportedRecognitionLanguages` returned **en-US only**.
The adapter uses CPU-only requests, disables language correction, reads image
bytes from stdin and writes a bounded JSON response to stdout. Core dumps are
disabled. Errors return nonzero status; Python discards stderr and emits a
safe incomplete-screening error. Each subprocess has a 30-second timeout;
`subprocess.run` kills/waits on failure or interruption. The native result is
validated for finite confidence and normalized rectangle geometry.

Primary references consulted:
[Apple text recognition](https://developer.apple.com/documentation/vision/vnrecognizetextrequest),
[Apple face rectangles](https://developer.apple.com/documentation/vision/vndetectfacerectanglesrequest),
and the locally installed macOS 10.15 Vision headers. This experiment does not
establish portability to another OS/revision or a complete privacy assessment.

Initial real evaluation (five generated images, no real people):

| Synthetic fixture | Detector/gate result | Interpretation |
|---|---|---|
| Teaching text and publication date | 2 lines, minimum confidence 0.5, no face | True negative for identifiers |
| Labelled name | Blocked after OCR | True positive |
| Email | Blocked after OCR | True positive |
| Unlabelled full name | Passed | False negative |
| Schematic face plus teaching text | Face count 0; passed | False negative |

Observed combined screening: TP 2, TN 1, FP 0, FN 2. This tiny challenge set is
not a sensitivity estimate for real faces or privacy. Confidence was 0.5 on
all five fixtures; first-run per-image durations were approximately 2.9–5.9 s.
There is no successful real face-positive fixture; that path is doubled only.

An initial development trial, before applying the qualification refusal,
verified real extraction/original equality/coordinates for PNG, JPEG and PDF
with explicit PRISM scientific metadata and blocked generation. Those trials
were memory-only, not durable application imports. The final evaluator instead
asserts production refusal for each format. Its experimental results do not
pass through an acceptance override or mutate the production gate.

## Pipeline and preserved guarantees

- Original bytes remain in the existing transactional BLOB columns (historical
  SQL name `original_pdf` retained for compatibility); SHA-256, media type and
  regions are attached to source metadata. No new raw-file store is introduced.
- Regions are OCR lines with page number and `(x0,y0,x1,y1)` normalized to the
  original page/image, origin at top left. Original + coordinates identifies
  the source region without storing a separate crop. Bounds must be finite,
  nonempty and within [0,1]. Every region is unconfirmed in 04.2.
- Text-PDF behavior remains intact. Raster candidates are dispatched from
  original content, re-screened/re-extracted on repository verification, and
  compared with the supplied payload. Flags, dates, coordinates and text
  cannot substitute for an original. Tampered validation flags are refused.
- PNG/JPEG decoding rejects animation, alpha/palette images, EXIF, unknown or
  opaque metadata (including ICC), oversize images and malformed payloads.
  Only bounded textual bibliography and recognized XMP namespaces are handled;
  metadata is checked before a clean in-memory raster is passed to the engine.
  These restrictions intentionally exclude many otherwise ordinary images.
- Scanned PDFs are limited to 20 pages, one unmasked full-page image per page,
  no text overlays, mixed pages, drawings, annotations, widgets, links,
  attachments, password, crop or rotation. Embedded image metadata and outer
  PDF metadata are checked; processing never bypasses the existing text gate.
- Limits: original and native input 20 MiB, decoded/rendered image 16 million
  pixels, 10,000 native lines, bounded native result size, 30 seconds per native
  subprocess and a checked 60-second raster-document budget. The document
  budget is checked between operations, not a hard watchdog around Pillow or
  PyMuPDF parsing. No arbitrary-input resource-exhaustion guarantee is claimed.
- A date still requires explicit front-page publication/update wording or
  recognized document-level PRISM metadata. Filesystem/EXIF dates do not count.
  An OCR date line below 0.98 confidence is refused unless independent recognized
  scientific metadata supplies the date. The threshold is conservative policy,
  not a calibrated scientific accuracy claim. All OCR content remains blocked
  for generation even above that threshold.
- `SourceDatePolicy` has a storage-only `allow_unconfirmed` option. Normal
  scientific evidence/retrieval keeps the default refusal; direct agent and
  graph calls also refuse pending OCR before any model context is constructed.
- Generic source-upload API and typed original download are prepared with the
  same owner and declaration checks. The old PDF endpoint remains compatible.
  Filename/type mismatch is refused. Upload parsing stays bounded and in RAM.
  Audit records carry engine/pending/date/policy metadata, not OCR text.
- A pending extraction status is available in FR/EN. There is no original-region
  review UI, correction endpoint, fabricated actor/confirmation or other 04.3 work.

## Automated evidence

`app/tests/test_raster_sources.py` and `app/tests/test_raster_guards.py` explicitly
separate doubled engine behavior from production refusal and native experiments.
They cover all three formats, originals/regions after restart, owner-only typed
download, audit, deletion, identifier/face/empty-result refusal, missing/uncertain
date, metadata refusal, invalid regions, forged extraction, size/time limits,
timeout arguments and error redaction, and direct evidence/agent blockers.
Rejected API requests leave SQLite snapshots and file inventories unchanged;
raw synthetic identifiers are absent from response errors and captured logs.
The full existing suite retains transaction, interrupted-deletion, stale-write,
ownership and cleanup regression coverage. Positive real detection of faces,
real interruption during native execution and deployment on other OS versions
remain unverified; exception-injection tests are not claimed as those trials.

Red/green history: first raster tests **3 failed** against the old PDF-only
pipeline; after implementation **3 passed**. First full regression run:
**275 passed, 1 skipped, 6 warnings**. Expanded focused run: **29 passed,
6 warnings**. Ruff initially found eight fixture-import F811 issues, fixed by
using the repository's fixture-alias convention. Final full run: **305 passed, 1 skipped, 6 warnings** (115.32 s), exit 0.
Ruff, compilation, dependency consistency and diff whitespace passed. The final
native evaluation exited 0, reproduced the same two false negatives and proved
production refusal for all three formats. Its per-image timings were 9.2–13.8 s
while the regression suite was also running; these are not latency guarantees. No failed check is counted as a pass.

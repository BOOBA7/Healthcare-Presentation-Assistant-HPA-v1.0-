## Supported subset and resolution of the 04.2 blocker

04.2's blanket raster refusal has been replaced by a stricter local gate:

1. Run local Apple Vision OCR and its face request under the same OS sandbox
   denying file writes and network access, with a subprocess timeout.
2. Refuse a reported face, known identifiers or a possible capitalized full name.
   The additional name heuristic applies to raster text, filenames, metadata
   and human corrections; it deliberately overblocks some headings.
3. Accept only near-monochrome pixels. Mask the OCR rectangles with a two-pixel
   allowance for glyph rounding. Any remaining pixel darker than 245/255 causes
   incomplete-screening refusal. A diagram, schematic face, stamp or image noise
   outside recognized text therefore cannot pass just because OCR found text.
4. Preserve the prior metadata, date, source-size, image-size and page limits.

This is a **text-only raster subset**, not general image privacy detection.
Native face detection still misses the schematic face; the residual-pixel gate
refuses it. Content incorrectly enclosed inside an OCR rectangle and names or
identifiers outside the implemented heuristics remain limitations. The original
04.1 fourteen-text-fixture results (including three misses) remain historical
and are not retroactively rewritten as successes.

Available here: English OCR only; clean monochrome PNG/JPEG and simple full-page
image-only PDF, with inspectable metadata and a reliable scientific date. Figures,
photos, noise, alpha, palette images, EXIF, opaque/unknown metadata, mixed PDFs,
rotation/crop, interactive content and unsupported engines/platforms fail closed.
Many ordinary files are intentionally refused. The installed OCR's observed
confidence is 0.5, so its textual date alone does not satisfy the existing 0.98
policy: the successful native fixtures contain explicit PRISM scientific date
metadata. Undated/uncertain-date sources cannot be rescued by an unsupported
user declaration. This limitation is visible beside the upload control in FR/EN.

No Tesseract/EasyOCR dependency was installed. The optional native adapter is
built from the repository source before processing input:

```sh

```

Binary output remains ignored under `app/interfaces/ocr/.build/`. No binary,
image input or output temporary files are committed. If the binary or its OS
confinement is unavailable, ingestion refuses rather than falling back to an
unconfined process or an external provider. See [04.2](04.2-raster-import-evidence.md)
for the initial native experiment, licence/platform observations and limits.

## Human review and provenance

Authenticated owners can open **Review OCR / Vérifier l’OCR**. The API supplies
the original crop, initial OCR value, editable value and previous confirmation
for every line. Crops are rendered in RAM from the verified original plus its
stored normalized top-left coordinates. Responses use `Cache-Control: no-store`;
the browser uses revocable blob URLs, not local storage for image/text payloads.

Each line has an unchecked confirmation box. Editing a value clears its check;
submission stays disabled until original images have loaded and every line is
explicitly checked. The backend independently requires every index exactly once.
It does not accept a client-provided actor, time, provenance or approval flag.

A review records, for every region:

- the unchanged original OCR value and source hash;
- the corrected/confirmed value;
- the authenticated owner and server UTC timestamp;
- an append-only review batch and `user_confirmed` provenance.

OCR regions and original bytes remain immutable. Effective page text and local
retrieval chunks use the confirmed values; citations still match exact effective
page text and retain the original coordinate/history link. Source details,
evidence prompts and local citation labels expose `user_confirmed`. This label
means human transcription review, never scientific correctness.

A private runtime receipt is issued only after matching review history against
the owner's canonical persisted source. It is not deserializable from client
JSON. Reverification rebuilds the original extraction and reapplies its verified
review history; payload/region/date tampering fails. Direct repository saves
cannot create or change review history. A source review revision fences stale
form submissions. A numeric test preserves initial `25` while persisting the
confirmed `2.5` with the same original region.

All review updates and audit events commit in one SQLite transaction. Every
attached Project receives the new effective text, invalidated downstream
approvals/content, cancelled stale jobs and refreshed chunks. Managed old exports
are queued through the existing resumable cleanup path. Audit failure rolls the
whole operation back. Re-review appends history and invalidates dependants again.
Permanent source/account deletion removes review content with the source; audit
identities remain without raw quotations according to the existing policy.

Unchanged persisted sources can be carried through saves/deletion without a live
OCR rerun **only when the complete payload, original bytes and SHA-256 match
already accepted owner-scoped records**. Shared text/metadata and review-authority
checks still run. New/changed content and scientific use require original
verification. This avoids making removal of one source depend on OCR availability
for a different unchanged source. A dedicated offline-engine deletion test passes.
